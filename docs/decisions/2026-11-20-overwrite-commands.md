# Overwrite commands (#76)

- **Question:** which commands handle the files a program wrote into Overwrite, and how do they behave?
- **Decision:** `nvmod overwrite list` (each file with the enabled Mods that hold the same path, ignoring case), `create-mod <name> [<glob>...]` (moves all or the matching files into a new Mod at the top of the list, keeps the folders, lists the plugins at its top level as inactive in `loadorder.txt` only; a name clash or a glob that matches nothing is refused), `move <path> --to <mod>` (a file or folder; refused when the Mod already has a path, nothing moves), `delete <path>...` (to `.nvmod/trash/<journal id>/overwrite/`), `sync [--to <mod>]` (a file with one provider goes to it and the Mod's copy goes to the trash; several providers are refused unless `--to` names one of them; a file nobody provides never moves). Globs use `*`, `?` and `**`, ignoring case; a pattern that names a folder takes everything under it. Existing folder spellings in the target Mod are kept. Empty folders left in Overwrite are removed. All are journaled as `lifecycle` (rollback restores every file and folder), refused while the game or Mod Organizer runs, and stage the Profile again.
- **Why:** the ticket. Globs are positional words after the name because options take one value. Providers are the enabled Mods: a disabled Mod is not in the tree the program saw. `--protect` and the sweep after a run are #75.
- **Revisit:** no.
