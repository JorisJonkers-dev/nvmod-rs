# User catalogue overlay (#71)

- **Question:** may a player add NVSE plugin entries to the catalogue without editing the shipped file, and within which limits?
- **Decision:** yes, as data only. `nvmod catalog`, `nvmod doctor` and `nvmod verify` read `catalogue.d/*.toml` from the config directory (`NVMOD_CONFIG_DIR`; else `$XDG_CONFIG_HOME/nvmod` or `~/.config/nvmod`; `%APPDATA%\nvmod` on Windows) when no `--catalog <file>` is given. Entries use the shipped schema and need a `[plugin.provenance]` table; `[[mod]]` tables are refused. Overlay entries carry `source = "user"` (a file cannot set it), the Doctor reports each present one as `catalog.user-entry`, and the plugin rows of the Mod Organizer 2 report carry `catalog_source`. An entry can only be `external` (it never says what nv-rs provides), never reuses a shipped or earlier id or DLL (`catalog.overlay-clash`, entry ignored), and may only refer to known ids. Limits: 32 files, 64 KiB per file, 256 entries in all. A bad file is ignored with a warning finding (`catalog.overlay-invalid`, `-too-large`, `-too-many`, `-claim`); the rest of the catalogue loads.
- **Why:** the overlay widens recognition, which is read only and reversible, and cannot widen a support claim. The caps keep a hostile or broken file from slowing the Doctor. The recommended option was taken because the owner decision was not available overnight.
- **Revisit:** if players need overlay entries to override a shipped entry's fields, or to claim support (#86 classes).
